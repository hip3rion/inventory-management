Data Flow — A Filtered Request

  1. User changes a filter

    FilterBar.vue writes to one of four shared refs — period, location, category, status.

  2. Composable holds the state

    useFilters.js declares its refs at module scope, so every component that calls the composable reads the same singleton instance.

  3. View reacts and requests

    The active view calls getCurrentFilters() and passes the result into the API client.

  4. Client builds the query string

    api.js appends only non-'all' values to URLSearchParams, so a neutral filter is simply omitted from the URL.

  5. FastAPI receives typed query params

    Each param arrives as an Optional[str] on the route function.

  6. Server filters in memory

    apply_filters() narrows by warehouse, category and status; filter_by_month() handles both YYYY-MM and quarter keys such as Q3-2025. Filtering rebinds a local name rather than mutating the loaded lists.

  7. Pydantic validates the response

    Routes declare response_model, so a fixture whose shape drifts from the model surfaces as a server-side error rather than reaching the UI.

  8. Vue stores raw data, derives the rest

    The JSON lands in a ref; totals, groupings and chart series are computed from it and re-evaluate only when the underlying ref changes.

  9. Template renders

    Tables and inline SVG charts read the computed values. No chart library is involved.

Observations

Six API client methods target endpoints that do not exist

api.js defines getTasks, createTask, deleteTask, toggleTask, createPurchaseOrder and getPurchaseOrderByBacklogItem, but main.py registers no /api/tasks or /api/purchase-orders routes. Verified live: both return 404. TasksModal.vue and the purchase-order flow depend on these.

views/Backlog.vue is unreachable

The router registers six routes and none of them point at Backlog.vue; nothing imports it either. Backlog data is rendered inline inside Dashboard.vue instead, so the standalone view is dead code.

purchase_orders.json is empty

The file contains [], so the has_purchase_order flag computed in /api/backlog is always false. With no POST route to create one, that flag cannot currently become true.

Writes cannot persist by design

mock_data.py reads the JSON files once at import into module-level lists. There is no write-back, so any mutation would live only until the process restarts.

Inventory carries no time dimension

/api/inventory accepts only warehouse and category. The period filter is inert on inventory-only views because the fixtures have no date field to filter on.

Demo-grade security posture

CORS is allow_origins=["*"] with allow_credentials=True, and useAuth hardcodes isAuthenticated = true. Appropriate for a local demo, not for deployment.
